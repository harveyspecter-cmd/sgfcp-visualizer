Fault Tolerance

Weight drift accumulated over 5,000 steps (20 trials, 64 simulated nodes) as a fraction of nodes randomly fail to deliver their Phase 2 delta contribution each step.

Weight drift vs. per-step node failure probability
InterpretationA missing Phase 2 contribution only biases the running correction with slightly stale data rather than blocking the job outright, unlike standard barrier-synchronous AllReduce, where a missing node stalls every other node until it recovers. As a result, weight drift grows gracefully and sub-linearly with the failure probability, which lines up with known results for asynchronous SGD when gradients are occasionally dropped.

Methodology & Run Parameters

Full generative model and run configuration for reproducibility.

Gradient process

Each of the 4 layer types (Embedding, Attention QKV, FFN, and LayerNorm or Bias) is modelled as a per-coordinate AR(1) process. Its autocorrelation ramps from a low warmup value up to a high steady-state value over the first 500 steps, reflecting the way gradient temporal correlation is typically observed to rise once a model moves past early training. On top of that base process, rare shock events, standing in for loss spikes, learning-rate transitions, and gradient clipping, are injected as randomly triggered noise bursts, with a higher chance of occurring during the warmup phase than later in training.

Honesty noteThis is a calibrated numerical model of gradient dynamics, not a live multi-GPU training run. It validates the SGFCP algorithm's math, its compression behavior, and its fallback logic end to end in software, using synthetic gradient traces built from the AR(1) process described above rather than gradients captured from a real model. Running the same pipeline against real captured gradient tensors from an actual training job is the recommended next step before any hardware integration is attempted.
